# Part 4 用户验收指南：申请管理与事件时间线

Part 4 已进入 `user_acceptance`。本阶段记录用户已经执行的投递及后续流程，不自动投递、不联系招聘方、不读取邮箱，也不调用或开发 OpenCLI。

## 1. 升级数据库

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m career_console db migrate
.\.venv\Scripts\python.exe -m career_console doctor
```

迁移会先创建 SQLite 一致性备份。预期：

```text
DB revision  20260724_0005  20260724_0005  PASS
```

如迁移失败，不要删除数据库或备份。

## 2. 启动

```powershell
.\.venv\Scripts\python.exe -m career_console serve
```

打开 `http://127.0.0.1:8765`，侧栏应出现“申请看板”和“事件审查”。

## 3. 验收前提

- 岗位池中至少有一个真实岗位。
- 该岗位至少有一份 Part 3 生成并确认的 Final 材料。
- 请选择你确实已经投递或准备投递的岗位；系统不会代替你执行外部操作。

## 4. 实际验收流程

1. 进入“申请看板”，选择真实岗位并创建流程；有 Final 材料时状态应为“待投递”。
2. 打开申请详情，选择实际使用的 Final 材料，填写真实投递时间，点击“确认投递并锁定材料”。
3. 确认状态变为“已投递”，时间线出现 `application_submitted`，材料快照显示正文 hash、事实集合 hash 和 PDF SHA-256。
4. 手动增加一个真实事件，例如“网申确认”“笔试”或“面试”，确认看板和详情状态同步变化。
5. 尝试选择一个不符合当前阶段的状态；系统应返回 `invalid_application_transition`，且时间线不增加事件。
6. 对刚才的事件执行“更正时间或备注”；原事件应保留并显示为已 supersede，新事件应引用原事件，当前状态不应倒退。
7. 在“添加待审事件候选”中创建一个候选，确认申请状态不立即变化。
8. 进入“事件审查”，确认一个准确候选；它应进入时间线并推进状态，ReviewTask 应记录确认结果和处理人。
9. 再创建一个不准确候选并拒绝；状态不得变化，拒绝原因和审计结果应保留。
10. 停止并重新启动服务，确认状态、完整历史、材料快照、更正和审查结果仍存在。
11. 流程结束后可归档；归档会新增事件，而不是直接覆盖历史状态。

## 5. 关键边界

- `submitted` 必须由用户确认，并至少绑定一份同岗位的 Final 材料。
- 同一岗位只建立一个申请流程；重复创建会返回原流程。
- 页面写操作使用版本号防止并发覆盖，过期页面会收到 `version_conflict`，刷新后再操作。
- 重复提交同一命令不会产生重复时间线事件或材料快照。
- 状态由不可变事件流重建；更正通过新事件 supersede 原事件。
- EventProposal 在用户确认前不能改变申请状态。
- 本阶段不执行自动投递、邮件同步、提醒或完整漏斗分析。

## 6. 反馈格式

请提供失败步骤、当前状态、目标状态、页面提示、事件时间和预期结果。可提供脱敏后的备注，但不要提供账号、Cookie、Token、API key 或招聘方私人联系方式。

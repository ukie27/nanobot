# Part 7 用户验收指南：只读 IMAP 邮箱 Connector

Part 7 当前仍在开发收尾，本指南供开发基本完成后的统一验收使用。本阶段只读取一个 IMAP 账户的 `INBOX`，扫描窗口最长为最近 30 天，不会发送邮件，也不会标记已读、移动、复制或删除服务器邮件。

## 1. 升级与诊断

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m nanobot career db migrate
.\.venv\Scripts\python.exe -m nanobot career doctor
```

数据库预期为：

```text
DB revision  20260724_0010  20260724_0010  PASS
```

启动本地应用：

```powershell
.\.venv\Scripts\python.exe -m nanobot career serve
```

打开 `http://127.0.0.1:8765/message-center`。

## 2. 准备测试邮箱

1. 在邮箱服务商设置中启用 IMAP，并确认服务器支持 TLS（通常为端口 `993`）。
2. 使用邮箱服务商生成的“客户端授权码”或“应用专用密码”，不要使用网页登录密码。
3. 记录测试邮件当前的已读/未读状态；建议至少准备：面试通知、笔试/测评、拒信、Offer、普通无关邮件各一封。
4. 不要把授权码粘贴到终端、日志、Issue 或验收记录中。

## 3. 配置与连接测试

在“消息中心 → 邮箱设置”中：

1. 填写邮箱地址、IMAP TLS 主机、端口和登录用户名。
2. 输入授权码。授权码写入 Windows Credential Manager，SQLite 只保存 `secret_ref`，页面和 API 不会回显授权码。
3. 首次范围可选择最近 7、14 或 30 天，服务端硬限制不超过 30 天。
4. 勾选“启用十分钟轮询”，保存设置。
5. 点击“测试只读连接”，预期显示连接正常和 `UIDVALIDITY`。

连接失败时，只核对主机、端口、用户名、IMAP 开关和授权码。不要将真实授权码发给开发人员。

30 天以前的投递、笔试、面试、Offer 或拒绝进度不从邮箱回溯。请在申请看板打开对应申请，按北京时间手动添加已确认事件。

## 4. 首次同步验收

1. 点击“立即同步”。
2. 检查同步记录的发现、新增、重复和错误数量。
3. 检查 Cursor 中的 `UIDVALIDITY` 和 `Last committed UID` 已更新；页面时间明确显示为北京时间。
4. 在 Message Center 核对四类结果：招聘相关、可能相关、无关、未知。
5. 核对笔试、面试、时间调整、拒信和 Offer 标签。
6. 招聘相关邮件应只显示有限证据摘录；附件只显示文件名、媒体类型和大小，不保存附件内容。
7. 无关邮件不得显示或长期保存正文。
8. 大于 10 MiB 的邮件只保留 Header 和去重信息，不读取完整正文或附件；畸形字符集和非法时间字段不得阻塞后续邮件同步。
9. 回到邮箱网页，确认同步前未读的邮件仍保持未读，所有邮件目录和数量未发生变化。

## 5. Application Proposal 验收

先确保系统里存在一条已经投递、且公司/职位能与测试邮件对应的 Application：

1. 同步对应的面试、笔试、拒信或 Offer 邮件。
2. Message Center 应显示“已创建待确认 Proposal”；匹配不足时显示“需要人工关联”，用户可以选择现有申请后生成待审 Proposal，系统不得猜测写入。
3. 在确认前查看申请时间线，状态不得变化，也不得生成新的面试/笔试 Reminder。
4. 点击“前往事件审查确认”，检查邮件主题和有限证据摘录。
5. 确认 Proposal 后，检查 ApplicationEvent 已写入；对于带时间的笔试/面试事件，检查既有任务模块派生的 Task/Reminder。
6. 拒绝另一个 Proposal，确认它不改变 Application 状态。

## 6. 增量、重启与幂等验收

1. 再次点击“立即同步”，同一 UID 不得创建重复消息或 Proposal。
2. 向测试邮箱发送一封新的招聘样例邮件，等待十分钟轮询或手动同步。
3. 只应新增这一封邮件，`Last committed UID` 向前推进。
4. 停止并重新启动 Career，再同步一次，确认从已提交 Cursor 继续。
5. 如邮箱服务器发生 `UIDVALIDITY` 变化，Connector 会重新按首次范围对账，数据库唯一约束仍阻止同一 UID 版本重复写入。

## 7. 删除与隐私验收

1. 点击“删除账户”并确认。
2. 邮箱配置、同步消息、候选记录、运行记录和 Cursor 会从本地数据库级联删除。
3. 对应授权码会从 Windows Credential Manager 删除。
4. 服务器邮箱中的邮件、目录、已读状态不受影响。

## 8. 安全边界

- IMAP 适配器只提供 TLS 登录、`SELECT readonly=True`、`UID SEARCH` 和 `UID FETCH BODY.PEEK`。
- 连接和读取采用 30 秒超时；服务器未提供有效 `UIDVALIDITY` 时同步失败且 Cursor 保持不变。
- 没有 `STORE`、`MOVE`、`COPY`、`DELETE`、`EXPUNGE` 或 SMTP 能力。
- 邮件正文中的提示词、链接或“系统指令”不会执行，也不会触发 Agent 工具。
- 分类和提取使用本地确定性规则，不把完整邮箱正文发送给模型。
- 正文读取、文本提取和附件元数据数量均有固定资源上限，超大邮件不会进入完整 MIME 解析。
- 单轮最多处理 500 封；超过上限的积压由后续轮询继续读取，Cursor 不得越过尚未处理的 UID。
- 用户确认 Proposal 前，不写 ApplicationEvent，不改变申请状态，不派生 Reminder。

完成以上场景后，请反馈失败步骤、页面提示和脱敏后的邮件类型；不要提供授权码或完整敏感正文。
